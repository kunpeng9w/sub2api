# 从当前分支升级 v0.2.22 的合并计划

日期：2026-11-17（Asia/Singapore）。状态：实施中，行为选择已由用户确认。

## 1. 合并原则

**相同功能优先采用上游逻辑，以减少长期维护差异。** 当前分支是合并起点，不是所有现有行为必须保留的约束。

1. 上游已覆盖的刷新、缓存、错误码、窗口显示和状态推导，优先直接复用上游实现及测试。删除被替代的本地实现、重复状态和配套测试要求，避免同一功能长期维护两条链路。
2. 上游未覆盖的定制能力，通过独立服务、组件或最小接入保留。每个接入点必须说明必要性并有回归覆盖；不为保持旧测试通过而重新包回整套本地引擎。
3. 与上游直接相反的产品规则单独登记，明确它是“接受上游行为变化”还是“需要继续保留的业务定制”。当前已有某段代码，不足以证明它必须成为例外。
4. 权限范围、严格出口和已执行数据库迁移属于必须审查的边界。优先复用上游已有机制，补足本项目实际需要但上游未覆盖的部分。
5. 若发现上游可复现的问题，先记录触发条件与测试证据；必要修复保持最小，独立提交，并记录将来删除补丁的条件。不能把“本地更严格”当成默认偏离上游的理由。
6. Git 合并逐块审查，不能整文件覆盖或使用 `-X ours`；选择上游功能逻辑仍需保护同文件内独有的定制接入。

## 4. 额度后端整合方案

### 4.1 刷新路径

以 v0.2.22 的 `getOpenAIUsage`、`shouldRefreshOpenAICodexSnapshot`、`shouldProbeOpenAICodexSnapshot`、`probeOpenAICodexSnapshot` 和快照持久化为功能基准。

- 保留上游普通账号、Spark、受限读取三个分支的职责。不要将本地 `queryOpenAIUsageSnapshot` 重新插入普通账号流程，导致名义上上游优先、实际仍运行本地引擎。
- 上游已满足的 TTL、force、Spark 无 WSv2 仍能更新等行为，保留原测试及断言。
- 审查当前入口、批量入口、passive 入口和监控入口的调用点，统一到上游服务；旧 helper、失败缓存或 fallback 只有在全部调用点迁移后才能删除。
- 上游已有的自动重置通知按其功能单独审查，不能套用旧计划“所有显示刷新禁止通知”的全局限制。受限读取与定制监控的权限约束必须落实，不能隐式获得重置能力。

### 4.2 需要审查的定制接入

- 权限：先校验账号范围，再读缓存或启动请求。受限管理员不能通过共享任务参与完整权限模型探测。
- 监控：真实 `monitorrequest` 上下文的额度查询、账号出口和执行锁生命周期属于专门接入。优先复用上游 QueryUsage，缺少相应分支时补最小适配；普通账号页面不因此变回全局 API 优先。
- 出口：上游 HTTP probe 与 quota API 均需遵守本项目账号代理、严格出口和审计。不能只因选择上游网络调用实现就绕过出口约束。
- 取消：审查上游有界超时与本地监控锁释放时机。若要保留共享查询，只保留满足具体场景所需部分；不把现有 singleflight 实现本身列为需求。
- 数据：Spark 凭据可来自父账号，快照写入对应影子账号；父子、不同账号和不同策略不能串数据。

### 4.3 字段与时间

- 采用上游 UtilizationUnknown、source、quota_refresh_failed 字段；监控不豁免查询失败，明确失效优先。
- 明确 0 与缺失不同，只有本地统计不能推定上游额度为 0%。
- 上游对过期窗口显示值的归零与快照观测时间分别验收；归零不能把 updated_at 改成当前时间。
- SampledAt、Estimate、WindowInactive 等字段仅在确有独有调用需求时保留；避免同一时间或状态存在两个计算来源。
- 单窗口更新允许保留另一窗口及其原 sampled_at，缺失时间显示未知；新使用率没有 reset 时清除旧 reset，不拼接旧重置或推算剩余额度。监控使用真实观测，不继承页面的过期归零。

## 5. 额度显示整合方案

以 v0.2.22 的 AccountUsageCell、UsageProgressBar、类型与 locale 为功能基准。

| 场景 | 验收依据 |
| --- | --- |
| 有真实额度观测 | 上游百分比、观测时间和重置时间逻辑 |
| 仅有本地统计 | utilization_unknown；保留统计，百分比显示 `—`，抑制额度倒计时 |
| 刷新失败、有缓存 | 上游历史额度提示和原观测时间；监控普通失败显示未知，明确凭据失效显示失败 |
| 刷新失败、无缓存 | 上游未知额度与失败提示；不虚构观测时间 |
| 已过期窗口 | 上游归零逻辑及相应测试；保留旧观测时间 |
| 手动刷新、账号切换或卸载 | 普通/主动/批量均在入队前固定账号及请求代次；显示、缓存、错误、finally 和卸载都校验 |
| 费用估算 | 上游已覆盖的保留上游实现，消除重复计算；独有估算单列保留 |
| 未激活窗口或额外采样提示 | 按确认后的定制边界通过少量 props/展示组件接入 |

具体工作：

1. 采用上游 `hasOpenAIQuotaObservation` 判断、error/error_code 提示、观测时间文案和格式，不并存本地重复提示。
2. 采用上游 active/passive 契约，检查组件和 API 调用方，旧测试不得要求所有 active 入口始终 source=active。
3. 补齐 PLAN-REVIEW.md 已定位的异步缺口：普通、主动、批量请求入队前固定账号 ID 与代次，响应和 finally 校验身份、代次与卸载。
4. 合并共享组件时覆盖 Claude、Gemini、Antigravity、Grok 和国产平台；避免未知额度支持破坏其他调用方。
5. 上游已有的次数、积分和显式重置流程直接复用；按上游刷新和缓存失效机制接入账号行。

## 6. 冲突与测试的处理准则

8 个冲突文件为 Makefile、account_usage_service.go、account_usage_service_test.go、channel_monitor_quota_fetcher_test.go、gateway_service.go、AccountUsageCell.vue、UsageProgressBar.vue、AccountUsageCell.spec.ts。

处理顺序：先上游额度模型与服务，后监控适配，再前端与批量入口，最后网关、Makefile 和所有自动合并文件。

- 上游回归保留普通页面的时间/source/未知窗口/过期归零语义；与已确认监控业务相反的防抖动断言明确映射为定制监控测试。
- 本地重复测试改为验证上游契约或删除重复覆盖；不能为保留本地实现而改写上游断言。
- 本地独有测试继续覆盖权限、出口、监控锁、已确认业务定制。被替换行为的旧测试应明确标注替代原因，不能把改断言冒充回归通过。
- 若两个测试对同一行为给出相反结论，先按第 3 节判断是否重复功能或独有需求，再处理测试，不能两套逻辑并存来同时满足。
- 每项最终保留的本地差异记录：需求、接入位置、为什么上游不能直接覆盖、验证用例、将来移除条件。
