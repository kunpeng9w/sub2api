# 官方 Claude 账号代理优先（2026-10-29）

状态：源码候选，尚未部署；独立 CI 验证中。线上仍使用此前版本，不能把本次源码调整描述为运行策略已经切换。

用户确认的优先级：**账号绑定代理 > 官方 Claude 默认 Mihomo 出口 > 其他账号的正常系统出站**。不按 Mihomo 进程状态自动改绑或更换出口。

| 场景 | 候选行为 |
| --- | --- |
| 官方 Claude 已绑定代理 | 转发、授权、刷新、用量与状态请求使用账号代理 |
| Mihomo 停止、启动或重启 | 已绑定账号继续使用原代理；未绑定官方账号仍请求 Mihomo，失败时报错 |
| 绑定代理缺失、禁用、到期、读取失败、连接失败或超时 | 阻止该账号请求，保留绑定，不改用 Mihomo、其他代理或直连 |
| 官方 Claude 未绑定代理 | `gateway.claude_egress.enabled=true` 时使用本机 Mihomo 入口 |
| 第三方 Claude 或其他账号未绑定代理 | 保持正常系统出站，不按模型名称强制分流 |
| 分组跨账号重试 | 保留，每个被选中的账号仍使用自己的出口 |

`gateway.claude_egress.enabled=false` 仍关闭官方 Claude 的应用默认出口；不改变系统 DNS/TUN。已经绑定账号的规则不依赖该开关。

## 修改范围

- 先验证账号代理，再考虑官方 Claude 的默认出口。无效绑定不会被当成未绑定。
- 移除账号创建、编辑、导入/复制及批量修改中的专用代理冲突限制；后台始终提供代理选择，并解释优先级。
- 在实际发送前重新读取并验证当前绑定。已绑定的官方账号也不能省略代理、传入旧代理或传入 Mihomo 来绕过检查。
- 官方域名传输边界和 OAuth 客户端保留已验证的显式代理；HTTP 重定向保持选定出口，禁止直连请求在重定向中自动切换为 Mihomo。
- 授权会话继续固定代理快照；管理端改绑、修改代理端点或凭据后应重新授权，不复用旧出口。
- 修正出口日志：绑定代理的官方账号记录为 `account_proxy`，不再误记为 `claude_mihomo`。

## TUN 与 DNS 边界

本次只改应用，不改变已经部署的定向网络规则。只读核对线上配置为：`route-address: [198.18.0.0/16]`、`auto-redirect=false`、`strict-route=false`、`dns-mode=disabled`，DNS 劫持列表为空；普通公网路由走 eth0。

外部 HTTP CONNECT 或 SOCKS 代理可接收官方域名并在远端解析，因此客户端连接的是代理端点，不需要先将官方域名解析为本机 Fake-IP。候选沿用既有 SOCKS 地址规范化与传输实现。本机 Claude DNS 分流和 Fake-IP 保护继续保留，不为独立代理开放官方直连。

账号若绑定本机 Mihomo 入口，仍然依赖 Mihomo；代理本身需要独立运行，其端点解析和网络路径也不能依赖已停止的 Mihomo。如果以后恢复全量 TUN，还需为独立代理端点配置绕行，应用代理优先本身无法改变内核路由。

Sub2API 只管理经过它的请求。其他程序访问官方 Claude 仍受原有 DNS/TUN 策略约束。
