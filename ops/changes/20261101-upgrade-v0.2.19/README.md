## 合并处理

- 唯一文本冲突为 `backend/go.sum` 的 7 处旧版本校验记录。双方 `go.mod` 完全一致，采用官方校验记录清理结果。
- 其余 36 个共同修改文件中的本地补丁增删内容均在合并预演中保留；252 个仅本地修改文件与原定制提交一致。此项是静态检查，不代替 CI 和业务验收。
- 保留严格账号出口、账号代理优先级、Claude 定向分流、HTTP/WS 出口审计、WS 每轮连接复用标记及客户端配置模板定制。
- `/api/v1/admin/accounts/egress-policy` 继续对受限管理员 API Key 默认拒绝，不向官方权限表增加授权。既有权限与注册路由测试增加此接口的拒绝场景。
- 首次 CI 发现自动合并的 Grok 模型目录准备函数已被上游拆分为三返回值，本地出口失败分支仍按旧签名返回一个错误。已适配返回值，新增当前代理绑定有效、仓库缺失、查询失败、代理缺失及停用时的同步回归，确保失效绑定不会发出上游请求或回退直连。
- 完整单元测试发现上游新加的两个 Grok 代理测试夹具缺少匹配的代理 ID 或启用状态，已补齐假数据以符合既有严格绑定约束；生产出口校验规则保持原样。

## 版本与产物

官方标签中的 `backend/cmd/server/VERSION` 仍为 `0.2.18`；本定制分支显式更新为 `0.2.19`。源码构建工作流使用既有版本解析脚本，写入真实源码提交、UTC 构建时间和 `source` 构建类型。

通过 GitHub Actions 执行完整单元/集成测试、前端关键测试与类型检查、lint、安全扫描、出口专项回归、运维隔离测试及嵌入前端的 Linux amd64 构建。本机不进行完整应用编译。

`Source and operations verification` 的构建 artifact 包含程序压缩包、压缩包与程序 SHA256、版本输出、Go 构建来源、模板测试日志和工作流地址，保留 7 天。最终结果见后续 `validation.json`。
